一、它是什么 仓库详梳（读者导向成稿）

产品形态四服务拓扑：Nginx(2026) → Gateway API(FastAPI + 内嵌 LangGraph) + Next.js 前端 + 可选 K8s Provisioner 一手（AGENTS.md:23-48，E1.1-01）。安装主推「把 Install.md 丢给 Claude Code/Codex 自动装」——Install.md 本身是写给 coding agent 的执行剧本（幂等/停止边界/成功判据，E1.3-01）
skills/ 是真机制五层设施：三激活路径（被动注入/延迟发现保 prompt-cache/slash 收权）→ per-thread 沙箱投影树（写隔离复制+签名 manifest）→ SkillScan 确定性 AST 扫描 → LLM 扫描 → CI waiver 双 merge（SHA 绑定+过期日+永不豁免 blocker，E2.1~E2.4）一手
plans/ 证伪全目录仅 1 个 2026-07 的 PRD 过程文件，运行时零消费者（E2.5-01）一手——真正的运行时「计划」是 Plan Mode（TodoList 中间件）
工程重心不在编排花式，在验证与边界：subagent receipt 双层验证（确定性 receipts + acceptance_checks 代码级验收，验收不过判 UNVERIFIED 不误判，E8.4-01）；fail-closed 密度极高；诚实自曝边界（"Local sandbox not a secure boundary"、"Gateway Admin = Code Execution"，E4.5/E4.8）一手
资源结构≈2 年 4900+ PR、核心作者 2 人、后端 693 测试文件、16 CI workflow、K8s Helm 全套（E5.2/E8.1/E8.2）一手——字节专人投入的公司级开源
用户真相官方亲口：「大家真正在用的不是 Research 能力——而是底下那套让 Agent 真正做事的运行时基础设施」（E1.2-04）自述-官方；高频抱怨 top1 = 部署安装（E1.2-04）一手

二、可比吗 三轴校准 + 意图裁定

层级轴它是产品框架（运行时 harness + Web UI + K8s）；flowkit 是编排方法论（会话内 skill 集，约定级不上引擎）→ 不同档
受众轴应用开发者/自托管玩家/企业部署方 vs Claude Code 重度个人用户——交集仅「把 agent 编排当正经工程做」的开发者，场景不重叠
意图裁定flowkit 经三源校准（README 自述 + 设计宪法 + CHANGELOG 行为偏好）并用户 sign-off：方法论自用为主 + 同行可见为辅，从未以大众 star 为 KPI → 「为什么它 82K 我们没有」按字面对照是伪命题；真命题 = 次要目标上哪些动作可迁移

三、概念同构判定 三问行为契约：解决什么/状态存哪/失败怎样

概念对三问摘要判定
skills ↔ skills三激活路径↔description 触发+Skill tool；SKILL.md+投影树↔SKILL.md+安装副本；SkillScan 阻断↔lint error+sync-check——三问全同向，连「确定性脚本守门」都同款真同构
plans ↔ .plan-feat-*/死档（无消费者无状态）↔活契约（STATE.md 活记忆+恢复协议+游标）同名异构
subagent 约束FIFO 准入并发 3 + 三轴帽 ↔ 同消息 ≤3 + 规模档位——并发默认 3 数字级独立收敛真同构
loop（cron）lease-fenced scheduler ↔ loops 层 CI cron + signal 登记——成熟度分叉（它多实例 lease 更深，我们登记体系更全）同构
最大发现不是差异，是同频 两个仓在毫无互通的情况下，于四个价值观独立收敛：验证是合同要件（acceptance UNVERIFIED ↔ IL-2 无新鲜证据不宣布完成）、诚实标注自身边界、拒绝默认并行（benefit-based ↔ 复杂度闸门）、记忆需要验证器（LongMemEval ↔ check_integrity）。上下两层栈，同一套工程伦理。推断
