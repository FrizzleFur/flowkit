# Goal Contract — 章节级精修周期（polish）

> 版本: v1 | 2026-09-12 | 状态: active | 用户指令: 充分吸收 learncc 结构与 CSS → 认知规划 → 对照不足 → 逐章抠细节, 每细节有详细计划与验收标准

## Objective

把教程站的整体体验推到 learncc 级: 清晰、结构化、高交互、形象。方法: 先系统性吸收 learncc 的结构/CSS/交互形成设计体系文档，再逐章差距审计，最后按审计逐章精修——每个细节改动静可验证。

## Success Criteria

| # | 标准 | 验收 |
|---|---|---|
| SC-P0 | 设计体系认知文档: 布局语法/排版阶梯/色板全阶/组件解剖/交互模式/动效曲线 六节, 全部带实测取值 | 文档落盘, 每节有 token 表 |
| SC-P1 | 差距矩阵: 11 章+封面+path+辅文 逐页审计, 每页差距条目含「差距描述/learncc 参照/修法/验收标准」四字段 | 矩阵落盘, 条目可执行 |
| SC-P2 | 逐章精修: 按矩阵分批修复, 每批修复后 CDP 逐章验收（对照验收标准逐条过） | 验收记录逐章留档 |
| SC-P3 | 六幕旗舰 CDP 深验补完（F1/F2/F4/F5/F6 播放实测——G2 断言已过, 渲染实测被本轮打断） | 巡检报告含五幕实测证据 |
| SC-P4 | Wave D 收尾: C4 预算槽视觉/C11 johari 2x2+喂模式分屏/C1 漏斗微调/S1 switch 动效——吸收完成后按新标准再评估是否仍需要 | 二次评估记录 |
| SC-P5 | 博客同步 + 两仓提交 | 提交记录 |

## Constraints

- 零依赖/零构建红线不动; SC5 锚点体系不动; 内容事实不动（本轮只动「呈现层与交互层」）
- 每个细节修复必须先有验收标准再动手（用户明令）
- 逐章推进, 每章验收通过才进下一章（用户明令「一步一步」）

## Non-goals

- 不改 skills 源码; 不做 Next.js 迁移; 不新增大功能模块

## Execution Strategy

Phase 1 吸收（design-system 深研 agent, CDP 实测 learncc 全页取样）→ Phase 2 差距矩阵（audit agent ×2 分半站扫描, 对照体系文档出逐页四字段差距条目）→ Phase 3 逐章精修批流（每批 ≤3 章, 修完 CDP 验收过再进下一批）→ Phase 4 终验（全站机检+六幕实测+博客同步）。
