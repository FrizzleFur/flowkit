# PPT Agent —— 策划师工作流

> 思路来源：linux.do 精华帖《应该是目前最强的PPT Agent》（sandun）。
> 核心洞察：专业 PPT 公司报价 1 万/页的秘密是"策划师"岗位——需求调研、资料检索、大纲规划都发生在设计之前。AI 完全能理解并执行这套人类专家工作流。

## 工作流总览（五阶段，顺序不可乱）

```text
需求调研 ──▶ 大纲策划 ──▶ 资料检索(可选) ──▶ 逐页生成 ──▶ 交付
  (问用户)    (金字塔原理)    (真实数据)      (SVG设计稿)   (preview+说明)
   阶段1        阶段2            阶段3           阶段4         阶段5
                  ▲
                  └── 确认点：大纲必须用户确认后才进入阶段4
```

## 阶段 1：需求调研（必做，禁止跳过）

拿到主题后**不要**直接生成。先向用户确认以下五项（一条消息问完，给默认值建议）：

1. **主题与目的**：汇报 / 路演 / 教学 / 产品介绍 / 复盘？
2. **受众**：谁看？什么水平？最关心什么？
3. **页数**：默认 10-15 页
4. **风格**：商务 / 科技 / 简约 / 活泼？有无参考图或品牌色？
5. **必含内容**：有没有必须出现的数据、结论、章节？

用户的回答将作为阶段 2 的"背景调研信息"。

## 阶段 2：大纲策划（金字塔原理 + 便利贴法）

读取 `references/outline.md`，按其中的架构师 Prompt 生成大纲。

执行要点：
- 把阶段 1 的回答注入为背景调研信息，大纲必须"有的放矢"，不凭空捏造
- 按 `[PPT_OUTLINE]` JSON 格式内部生成，转成**可读大纲**展示给用户（封面/目录/各部分/各页标题）
- **确认点（强制）**：展示大纲后停下，等用户确认或调整。每一页就是一张"数字便利贴"——用户可增删、调序、改标题。未获确认禁止进入阶段 4

## 阶段 3：资料检索（可选，按需触发）

当内容需要真实数据支撑（市场数据、财报数字、竞品对比）时：
- 对每个数据型页面，用 WebSearch 检索相关事实
- 检索摘要附到大纲对应页，作为阶段 4 的填充素材
- 纯观点型/内部汇报型 PPT 可跳过本阶段

## 阶段 4：逐页生成设计稿

先读 `references/svg-generation.md` 和 `references/bento-grid.md`，然后逐页生成：

- **每页一个独立 SVG 文件**，viewBox 固定 `0 0 1280 720`（16:9）
- 文件命名 `NN-slug.svg`：`01-cover.svg`、`02-toc.svg` …
- 内容来自大纲 + 检索数据，**禁止占位文本**（无 lorem ipsum、无"此处填写"）
- 生成全部页面后，写一个 `preview.html`（带左右翻页/键盘导航的极简查看器，内嵌所有页面）

## 阶段 5：交付

向用户输出：
1. 文件清单（每页一行，含标题）
2. 使用说明：`open preview.html` 翻页预览；单个 SVG 可直接拖入 PowerPoint（Office 2016+）中编辑；全选 SVG 拖入可逐页导入
3. 主动询问：哪几页需要调整？（收集反馈后可单页重生成）

## 输出纪律（每页 SVG 强制）

- **Bento Grid 卡片布局**：内容必须装进卡片，遵守 bento-grid.md 的留白与层级原则——卡片是 LLM 最可控的设计语言
- **色板一致性**：开工前根据用户风格偏好定义一次色板（背景/主色/强调色/文字色/卡片底色），所有页面复用同一组色值
- **中文字体 fallback**：`font-family="'PingFang SC','Microsoft YaHei','Noto Sans SC',sans-serif"`，标题可加 `'PingFang SC Semibold'`
- **文字防溢出**：卡片内文字预留 padding ≥ 20px；长文本主动分段或缩写，不硬塞
- **每页信息密度**：一个卡片一个论点；单页卡片 2-5 个为宜，超过就拆页
