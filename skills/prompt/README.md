# prompt

基于乔哈里视窗理论和 3S 原则的 Prompt 评分与优化工具：输入任意 prompt，输出评分报告、问题诊断与优化版本。

> SKILL.md 为单一事实来源，本 README 为人向导览快照（生成于 2026-09-08）。

## 解决什么问题

写 prompt 最常见的两类病：

| 病症 | 表现 | 后果 |
|------|------|------|
| 信息盲区 | 自己知道但没写出来：团队黑话、内部系统名、新造概念，默认 AI 也知道 | AI 猜测甚至编造，答非所问 |
| 冗长不聚焦 | 多个目标混杂、堆砌修饰词、低信息密度 | AI 无法确定主要目标，输出泛泛 |

本 skill 用两套理论分别对症：

**乔哈里视窗四象限定位盲区**（SKILL.md:L99-106）。以「用户知不知道 × AI 知不知道」划分四个象限，其中最危险的是**第四象限**——用户独有的知识（"我们团队的 XX 系统"、"公司内部规范"），AI 天然不知道。skill 通过限定词（"我们团队/公司/本项目"）、内部术语、无定义新概念等标识识别第四象限（SKILL.md:L110-113），并执行硬规则：识别为第四象限却未使用"喂模式"（举例法/定义字典/RAG）的，总分封顶 2.0/10，Critical 级；正确喂模式后可提升至 7.0-8.5（SKILL.md:L115-118）。

**3S 原则约束表达**（SKILL.md:L119-125）。

| Principle | 含义 | 检测方式 |
|-----------|------|----------|
| Single | 单任务聚焦 | 检测"和/并/以及"等连接词、多个动词短语 |
| Specific | 明确详细 | 有格式+范围+示例得 9-10 分；无格式无范围仅 2-6 分 |
| Short | 简洁扼要 | 冗余修饰、低密度 4-6 分；高密度 9-10 分 |

SKILL.md 头部原带一张评分效果图（alicdn 外链截图），展示评分报告的象限、各维度得分与问题诊断布局；因外链图在开源迁移后可能失效，此处不复述图片，实际输出样式见下文"最小使用示例"与 SKILL.md 的 Output Format 一节（SKILL.md:L211-242）。

## 触发方式

| 方式 | 输入示例 | 行为 |
|------|----------|------|
| 显式命令 | `/prompt 写一个冒泡排序` | `/prompt` 之后的**全部内容**即待优化 prompt，无需再说"优化"（SKILL.md:L32-34） |
| 显式命令（别名） | `/prompt-scoring` | 同上（SKILL.md:L17） |
| 自然语言 | "这个提示词怎么样"、"帮我优化这个提示词：xxx" | 从消息中提取 prompt 内容再评分（SKILL.md:L42-44） |
| 自动检测 | 输入超 200 字符且含角色定义/任务指令/约束词/格式说明等模式 | 先询问"是否需要评分和优化"，确认后才执行（SKILL.md:L22-24, L53-72） |

两种调用模式的区别（SKILL.md:L30-49）：

- **Command Mode**：`/prompt <content>`，斜杠后整段内容视为待评对象，包括英文 prompt（`/prompt As a senior developer, review my code` 也直接评分）。
- **Natural Language Mode**：由对话中的隐式关键词触发，skill 自行剥离"帮我看看""写得怎么样"等寒暄，只取 prompt 本体（"帮我优化一下这个提示词：写一个冒泡排序" → 提取"写一个冒泡排序"）。

## 核心架构

### 分析管道（Step 2-7）

评分按固定管道执行（SKILL.md:L86-95）：

```mermaid
flowchart LR
    S2["Step 2 提取 Prompt"] --> S3["Step 3 分析"]
    S3 --> S4["Step 4 选权重"]
    S4 --> S5["Step 5 计算总分 1-10"]
    S5 --> S6["Step 6 诊断问题"]
    S6 --> S7["Step 7 生成优化版本"]
```

其中 Step 3 同时判定象限归属、3S 合规度与场景类型；Step 4 按象限与场景选择权重；Step 6 产出按严重性排序的问题清单。

```
提取 ──> 分析(象限/3S/场景) ──> 选权重 ──> 算分 ──> 诊断 ──> 优化版本
```

### 评分体系：场景检测 + 维度加权

先判场景，再按场景分配权重（SKILL.md:L129-136）：

| 场景 | 判定条件 | 权重分布 |
|------|----------|----------|
| 简单任务 | 字数<100、单目标、无复杂结构 | 目标明确性 40% + 3S 30% + 基础清晰度 30% |
| 复杂专业 | Role-Based、工作流、约束 | 基础评分 50% + 深度评分 50% |
| 第四象限 | 独有知识、企业术语、新概念 | 目标明确性 20% + 示例/术语完整性 80% |
| 学习任务 | 含学习/理解/解释关键词 | 目标明确性 30% + 3S 30% + 表达清晰度 40% |

维度分两层（SKILL.md:L140-151）：

- **基础评分**（所有 prompt）：目标明确性 40%、3S 原则 30%、基础清晰度 30%。
- **深度评分**（条件触发：复杂专业 / 第四象限 / 含 Role-Based 结构 / 字数>200）：约束完整性、技能匹配度、工作流清晰度、示例/术语完整性，各 25%。

### 问题诊断：四级分级

问题按 Critical > High > Medium > Low 排序输出（SKILL.md:L153-184），Critical 三项为：第四象限未使用喂模式、多目标混杂、完全缺少成功标准。多轮对话型 prompt（追问/澄清/访谈类）另有"节奏四律"专项检查——延迟结论、一次一问、反形式主义、信息密度判据（SKILL.md:L186-195）。

### 优化策略选择

按诊断结果自动选择策略（SKILL.md:L199-205）：

| 条件 | 策略 | 方法 |
|------|------|------|
| 问题少（≤3）且无 Critical | 保留式优化 | 保留原有结构风格，只改问题部分 |
| 问题多（>3）且有 Critical | 重构式优化 | 重新设计结构，应用合适模板 |
| 完全不匹配最佳实践 | 模板化优化 | 推荐最合适模板，基于模板重建 |

分数与行动的对应关系：9-10 可直接使用；7-8.9 建议小优化；5-6.9 建议优化；3-4.9 需要重构；1-2.9 必须重写（SKILL.md:L311-319）。

## 最小使用示例

取自 SKILL.md 的第四象限实例（SKILL.md:L269-295），最能体现"信息盲区"诊断价值。

**输入**（自然语言模式，提取出的待评 prompt）：

```
审查我们公司的 XYZ 系统代码，确保遵循 YYY 规范
```

**诊断要点**：

- 象限：第四象限——"我们公司的"、XYZ 系统、YYY 规范均为用户独有知识，AI 不知道（SKILL.md:L275-277）。
- 问题：未使用喂模式，属 Critical 级第 1 项，触发 2.0/10 封顶规则（SKILL.md:L116, L159）。

**评分**：2.0/10（Critical）。

**优化后版本**（补定义字典 + 正反示例，即"喂模式"，评分升至 8.5/10）：

```
审查我们公司的 XYZ 系统代码，确保遵循 YYY 规范。

**定义**:
- XYZ 系统：我们内部的微服务框架，基于 Spring Boot
- YYY 规范：内部代码规范，要求类名用 PascalCase，方法名用 camelCase

**示例**:
不符合规范:
public class user_service { }

符合规范:
public class UserService { }
```

评分报告完整结构（基本信息、各维度得分、问题诊断、优化建议、优化版本五段）见 SKILL.md:L211-242。
