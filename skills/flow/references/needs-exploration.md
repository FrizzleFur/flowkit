# Stage 1.5: 需求探索

> 由 flow/flow-deep 共享。当优化后的任务表述中存在不确定项时触发。

## 触发条件

Stage 1 完成后，优化后的任务表述中存在以下任一情况:
- 技术方案描述模糊（如"优化性能"但无具体指标）
- 业务逻辑不确定（如"支持多币种"但未指定哪些币种）
- 影响范围不清（如"重构认证系统"但未说明边界）
- 存在 3 个以上不确定的关键决策点

**参考**: superpowers:brainstorming 的需求探索模式

## 行为

1. **不确定项识别**: 分析优化后的任务表述，列出关键不确定项（最多 5 项）
2. **评估明确度**: 对每个不确定项评分 0-10（明确度 < 7 的需要追问）
3. **主动追问**: 对明确度 < 7 的不确定项，使用 AskUserQuestion 向用户确认:
   - 每个问题最多提供 4 个选项 + 自由输入
   - 选项应包含合理默认值（标注 Recommended）
   - 问题应具体而非笼统（"需要支持哪些币种？" 而非 "还有其他需求吗？"）
4. **合并结果**: 将用户回答合并到任务表述中，生成"明确后的任务表述"
5. **记录**: 写入 findings.md 的"需求探索"章节

## 示例

```
任务: 重构支付系统，支持多币种

不确定项:
1. 具体币种范围（明确度: 3/10）→ AskUserQuestion
2. 支付方式范围（明确度: 5/10）→ AskUserQuestion
3. 向后兼容要求（明确度: 8/10）→ 无需追问

AskUserQuestion:
Q1: "需要支持哪些币种？"
  - CNY + USD + EUR + JPY（推荐）
  - 仅 CNY + USD
  - 自由输入

Q2: "需要支持哪些支付方式？"
  - 支付宝 + 微信 + 信用卡（推荐）
  - 仅支付宝 + 微信
  - 自由输入
```

## 跳过条件

不确定项 < 3 或所有不确定项明确度 >= 7
