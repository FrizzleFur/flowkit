# Stage 2 详细参考

## --think / --think-hard 思考维度

调用 Sequential Thinking MCP 进行结构化思考：

```
思考主题: <优化后的任务表述>
思考深度: 4K (--think) 或 10K (--think-hard)

思考维度:
  1. 任务分解: 将任务拆解为可独立执行的子任务
  2. 依赖分析: 识别子任务间的前后依赖关系
  3. 风险评估: 识别技术风险和潜在障碍
  4. 资源需求: 评估每个子任务需要的技能和工具
  5. 执行策略: 推荐并行/串行执行方案
  6. Superpowers 技能匹配（仅 `--deep` 时启用）: 根据子任务特征匹配 TDD/并发/审查技能
```

完成后，将思考结论展示给用户，并记录到 findings.md。

## --mermaid 图表类型

生成以下图表：
- **任务分解图**: 展示任务层级和子任务关系
- **依赖关系图**: 展示子任务间的依赖（哪些可并行）
- **执行流程图**: 推荐的执行顺序

## --discuss 三角色讨论流程

三角色讨论模式，适用于需要权衡决策的复杂任务：

```
针对任务: <优化后的任务表述>

选择三个最相关的角色进行讨论（根据任务类型自动匹配）:
  - 角色A: [如: 架构师] — 关注系统设计和可维护性
  - 角色B: [如: 性能工程师] — 关注执行效率和资源利用
  - 角色C: [如: 安全专家] — 关注安全性和风险控制

讨论流程:
  第一轮: 每个角色提出自己的方案和理由
  第二轮: 角色间互相质疑和补充
  综合: 整合三方观点，形成最佳方案
```

讨论结果记录到 findings.md 中。
