## 0. 核心判断（三角测量结论）

**本站内容件与 learncc 四标签一一对应, 缺的是组织容器与进度感**:

| learncc 四标签 | 本站已有对应物 | 现状问题 |
|---|---|---|
| Learn（长文叙事） | 机制长文主体 | 有, 但与演示混排在一条长滚动里 |
| Simulate（回放） | replay/组件 + 播放器 | 有, 但 inline 混排、无驻留位 |
| Code（看真相） | 本章源码锚点表 | 形态弱: 是引用表非「真相区」, 无复制/直链 |
| Deep Dive（深挖） | 批判小节 + propositions 引用 | 有, 但与正文平铺无收束感 |

**learncc 的组织精华**（走查+源码双源证实）: 章页四段式（页头→持久可视化+播放器→四标签→分页）; 增量叙事（Changes 表/LOC 一等公民/Compare 页）; 双坐标系（编号=构建顺序, 分组=架构归属）。
**learncc 的实测坑**（我们不复制）: 四标签在首屏折叠线下; 首页/Timeline/Layers 三份同构重复; Code 标签死端; Learn 5111px 无页内 TOC。

## 2. 章级方案（核心: 四段式分区容器）

**R5 · 章内分区容器**——把线性长滚动重组为 learncc 式四段式:

```
现状:  页头 → callout → 组件/长文/锚点表/批判小节 线性混排
改为:  页头（已有）
       → 持久演示区（本章主力组件上提常驻, 高度受控 ≤~420px）
       → 标签区 [ 怎么用 | 机制 | 源码锚点 | 深挖 ]
       → 上一章/下一章 双卡（fs-prevnext 推广到机制篇 8 章, S15 一并了结）
```

- 标签映射: 怎么用（30 秒上手, 保留）/ 机制（长文主体, 现正文）/ 源码锚点（锚点表升级, 见 R9）/ 深挖（批判小节 + propositions 引用）
- **折叠线纪律**（learncc 坑的反面）: 演示区高度受控 + 标签栏首屏可见
- 实现: **docsify-tabs 插件**（MIT, bp 实测存在; 钉版+SRI, 与 search 插件同待遇）——**待用户裁决**, 备选自写 ~50 行原生（组件体系一致性更好）
- 结构纪律: 锚点表从长文抽出进标签, h2 结构变化 → path-data/anchors 快照同步 + SC5 锚点体系核对
- **试点先行**: 1 章验证（推荐 ch6 组件最密）→ CDP 验收 → 推广 8 章

**R6 · 首屏摘要卡**: fs-callout 升级——一句话机制 + 「本章你将看到 3 件事」+ 预计时间。纯写作规范, 零代码。bp P0（首屏 57%/74% 眼动依据 + javascript.info 参照）。

**R7 · 页内锚点确认**: docsify subMaxLevel 确认开启, 机制长文 h2 全部可达（learncc 卡点「无 TOC」的反面）。~零成本。

- Timeline/Compare/Layers 页复制（learncc 同构重复坑）
- 动效滥用式入场体系全量铺开（NN/g「只对必须注意的元素动效」+ 否决区精神; 议点 1 降 P2）
