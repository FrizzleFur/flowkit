〇、站点架构总览

learncc 是「应用中心」站（Next.js）; 我们是「文档中心」站（docsify）。布局讨论的第一性问题: 借它的什么，放进我们的壳。

站点三层结构:
① 首页——大标题 + Start Learning 按钮 + 「The Core Pattern」代码卡 + Message Growth 循环动画（滚动进视口才播）
② 三个站级视图——Timeline（Learning Path 时间线）/ Compare（版本对比）/ Layers（五层组织）
③ 章节页 ×20——每章四标签: Learn（图文+可视化演示）/ Simulate（剧本回放模拟器）/ Code（源码）/ Deep Dive（深读）; 左侧 sticky 章节导航（五域色点分组）
关键观察: 它的每个演示都是「步进引擎 + 声明式数据」——不为一章写一次动画逻辑。这是我们最该搬的架构决策，比任何单个动画都重要。

一、P11 增长动画（首页 Message Growth）

行为实测: 角色芯片逐个 append，len 徽章同步递增（采样捕获 7→8→1 重置循环）; 滚动进视口才开演。源码: architecture/message-flow.tsx（useState/useEffect + interval + framer-motion）。

七、零依赖替换清单（framer-motion → 原生）

learncc 用法我们的等价物
motion 出场动画（chip/卡片滑入）CSS @keyframes + class 挂载（components.css 已有基础）
AnimatePresence 退出动画class 切换 + transitionend, 或教学场景直接瞬时移除
useSteppedVisualization扩展 replay.js: 步进状态抽为可订阅引擎, 面板注册 onStep(idx) 回调
lucide-react 图标内联 SVG path（3-4 个常用图标手嵌）
IntersectionObserver 触发原生 IntersectionObserver（本就原生, 直接用）
结论: learncc 的生动度不来自框架，来自「声明式数据 + 步进引擎 + 多面板」的架构与旁白纪律——零依赖路线完全可以追平。
