# Goal Contract — 原理交互可视化研究（iviz）

> 版本: v1 | 2026-09-12 | 状态: active | 用户四步流程为骨架

## Objective

把 flowkit 原理做成 learn-claude-code 级的生动交互: 盘点值得交互的 12-18 个原理点 → 每点独立子项目深研最适动效形态 → 综合成案并 review → 落地教程站。

## Success Criteria

| # | 标准 | 验证 |
|---|---|---|
| SC1 | 大纲清单: 12-18 个交互候选点，每点含大纲（原理一句话/交互要演示的 aha 时刻/候选动效形态/难度与价值评分/落位章节） | 清单文档落盘，逐点字段齐 |
| SC2 | 子项目深研: 每候选点一个子目录（研究笔记 + 交互设计稿: 状态机/画面分镜/技术选型） | subprojects/ 下逐点齐 |
| SC3 | 综合方案 + review: 汇总为实施方案（优先级排序/批量计划），经独立审查 | 审查报告 + 修订记录 |
| SC4 | 落地: 至少 TOP N 个新交互组件/升级实装到 site/ 并 CDP 实测可用 | 组件在站 + 端到端验证 |

## Constraints

- 动效技术: 原生 JS + SVG + CSS 动画全放开，**零框架零构建零新增 CDN 依赖**（2026-09-12 用户裁定）
- 候选范围: R3 全仓 ~70 机制筛 12-18（含已建 5 组件的升级候选）
- 节奏: 子项目分批并行（每批 ≤3 agent，用户裁定）
- SC5 同源纪律: 交互演示的机制行为须与 skills 源码一致（动画是演示不是改编）
- 既有站点只增量（site/ 现有文件不破坏）

## Non-goals

- 不引入动画库/框架; 不做 3D/WebGL; 不为动画牺牲移动端可用性
- 不在本周期内完成全部 18 点实装（SC4 只承诺 TOP N，N 在综合方案时定）

## Verification Plan

清单/子项目/审查三件文档机检 + 实装组件 CDP 端到端（复用本轮的诊断模式）+ Goal Verification 表。

## Execution Strategy（用户四步 + 裁定细化）

Phase 1 大纲盘点（三路并行: R3 全域挖掘 / learn-claude-code 动效形态库 / 既有 5 组件升级评估）→ 主会话综合成大纲清单 → Phase 2 子项目分批深研 → Phase 3 综合方案 + 独立 review → Phase 4 分批实装 + CDP 实测。
