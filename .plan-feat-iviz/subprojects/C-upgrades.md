# C 线：既有 5 组件升级空间评估

> 评估对象: `site/assets/interactive/` 下 replay.js / autodecide.js / switch-panel.js / budget429.js / johari.js。
> 对标: learn-claude-code 的 simulator（播放器语言 + 逐步旁白 + 调速）生动度。
> 红线（全局）: ① 现有 API 不破坏——`.fs-*` class、`data-script`/`data-ready` 协议、`FlowSite.fns` 注册、index.html 三保险引导（doneEach + hashchange + 800ms 自愈轮询）② 移动端可用 ③ 零依赖（原生 JS + SVG + CSS，无框架无构建）④ 风格保持现有 ES5 品味（var/function，docsify 无构建环境）。
> 通用注记: 所有动画方案默认配 `@media (prefers-reduced-motion: reduce)` 降级为无动画——成本约每组件 3 行 CSS，建议作为本线统一纪律。

## 1. replay.js（107 行 + 2 剧本）

### 现状

- **交互形态**: 播放器语言已齐——播放/暂停、单步、重置、0.5/1/2/4x 调速；首步预览吸引点击。这是五组件中唯一对标过 simulator 的（文件头注释自认「simulator 模式的原生 JS 化」）。
- **视觉**: 五角色色标签（用户蓝/主会话绿/工具橙/系统红）、annotation 旁白条（橙左边框）、白卡片蓝标题栏。
- **剧本质量**: 两部剧本旁白密度高（每步一条 annotation，讲机制不复述内容），是内容资产而非占位。

### 差距（vs simulator）

| 维度 | 现状 | simulator 水准 |
|---|---|---|
| 动效 | 消息**整块瞬现**，无打字机、无入场渐现 | assistant 消息逐字打出，「像正在思考」 |
| 状态反馈 | 播放/暂停有按钮文字切换；**当前步与历史步无视觉区分** | 正在发生的消息有呼吸态/高亮 |
| 进度感 | 无步骤计数、无进度条、**不能跳转**到某步 | 播放器有 scrubber/刻度 |
| 叙事性 | 消息与旁白**同时出现**，无节奏 | 先发生、后解读的两拍节奏 |

### 升级选项

**A. 播放器成熟化（轻升级，推荐）**
- 方案: ① assistant/system 消息打字机逐字输出（user 消息刻意整块出现——模拟「人是一次粘贴的」，反而更真实），打字速度与调速联动；② 头部加 `3/13` 计数 + 细进度条；③ 新消息 slide-in 入场，旁白延迟 ~400ms 淡入（先发生后解读）；④ 最新消息左侧蓝色边条高亮，历史消息降透明度至 .75。
- 技术: 打字用 `setInterval` 切片 textContent（无需 rAF）；入场/淡入纯 CSS `@keyframes` + `animation-delay`。
- 工时: 2-3h，约 +60 行。
- 分级理由: 纯表现层，结构/协议/剧本 JSON 零改动；**两处复用（ch4+ch8）杠杆最大**，是本线性价比第一刀。
- 页面长什么样: 点播放后，绿色「主会话」标签的消息文字像终端一样逐字滚出，打完的瞬间橙色旁白条从左侧滑入解说「这一关在干嘛」；顶部细进度条随每步推进，刚出现的消息左缘一道蓝光边条，两句之前的消息已经安静地退成浅灰。

**B. 步骤刻度导航（轻升级，可选叠加）**
- 方案: 头部下沿一排步骤圆点（每步一个，hover 显示 role + 首行摘要），点击即重放到该步。
- 技术: 圆点为 button，跳转 = 清空重渲染至目标步（复用现有 renderStep）。
- 工时: 1-2h，约 +40 行。
- 分级理由: 单步按钮已覆盖顺序消费，导航是回看场景的锦上添花——建议 A 落地后按需追加，不与 A 绑定。
- 红线自查: 移动端圆点行 flex-wrap 即可；零依赖无虞。

**C. Stage 关卡侧栏（重升级，暂缓）**
- 方案: ch4 剧本专属——左侧竖排十二关刻度尺，播放推进到对应 Stage 时该关卡点亮打钩，把「十二道关」从章节文字变成可见的关卡进度。剧本 JSON 增加可选 `stage` 字段。
- 技术: 协议向后兼容（无 stage 字段则不渲染侧栏，ch8 剧本不受影响）。
- 工时: 4-6h，约 +100 行 + ch4 剧本补字段。
- 分级理由: 教学收益强（关卡感是 ch4 核心隐喻），但触碰剧本协议 + 布局结构（移动端侧栏需折叠为顶部横条），维护面翻倍。**建议 A 落地后视真实效果再决定**，不预先承诺。

### 红线自查（A 方案）
- API: `data-script`/`data-ready`/`FlowSite.fns` 全不动，fetch 失败降级文案保留。
- 移动端: 打字机与进度条对窄屏无影响；slide-in 用 translateY 小位移避免横向滚动。
- 零依赖: setInterval + CSS keyframes，均为原生。
- 边界: 打字中途点暂停/调速/单步需中断当前打字（clearInterval 后立即补全该步文本）——这是 A 方案唯一的状态机新增，约 10 行，需覆盖测试。

## 2. autodecide.js（106 行）

### 现状

- **交互形态**: 8 题三选判定游戏（AUTO/TASTE/BLOCKED），进度（x/8 + 答对 n）、即时反馈（命中原则 + why）、完成画面（分数评语 + 再来一轮）。功能闭环完整。
- **视觉**: 灰底题卡、三色按钮、绿/橙反馈块。配色与全站体系一致。

### 差距

| 维度 | 现状 | 缺口 |
|---|---|---|
| 动效 | 反馈瞬现、卡片切换无过渡 | 反馈展开动画缺席 |
| 状态反馈 | 对错有色彩 | 无「判定发生」的仪式感 |
| 进度感 | 有文字进度 | 无图形进度条 |
| 叙事性 | **「P1→P6 顺序判定，命中即停」是核心机制，从未可视化**——反馈只说「P6 命中」，学习者看不到链条怎么走到 P6 | 判定链是隐形的 |

### 升级选项

**A. 判定链揭示动画（轻升级，推荐）**
- 方案: 答题后反馈区顶部先出一行六个原则胶囊 `P1→P2→…→P6`，逐个点亮走到命中项（串行 `animation-delay`，纯 CSS 可做），命中的胶囊定格放大，然后 verdict 弹出——把「顺序判定」变成看得见的 1.2 秒。
- 技术: 六个 span + CSS animation-delay 串联；顺手把文字进度升级为双色进度条。
- 工时: 2h，约 +50 行。
- 分级理由: 核心机制可视化，教学收益/成本比在本组件内最高。
- 页面长什么样: 选了 BLOCKED 后，一行六个小胶囊从左到右依次亮起，P1 亮了又暗（未命中）、P2 亮起定格变红放大——「命中即停」四个字第一次有了画面；下方绿/橙反馈块随后展开解释为什么。

**B. 最小动效包（轻升级，可叠加）**
- 方案: 反馈块 max-height 过渡展开、卡片切换淡入、连对 3 题显示连击标记。
- 工时: 1h，约 +25 行。分级理由: 氛围补充，单独做收益偏低，建议与 A 同 commit。

**C. 保留现状**
- 理由: 出题-判定-反馈-复盘-重开闭环已完整，8 题内容质量高（P1-P6 全覆盖 + 例外条款陷阱题）。若 iviz 排期紧，本组件可不动，工时让给 replay/budget/johari。
- **这是正当选项**——autodecide 是五组件中「功能完成度」最高的。

### 红线自查（A 方案）
- API 不动；胶囊行 flex-wrap 移动端安全；纯 CSS 动画零依赖。判定链文案直接复用 CASES 里已有的 principle 字段，无新增内容漂移面。

## 3. switch-panel.js（85 行）

### 现状

- **交互形态**: 7 个参数 checkbox → 12 个 Stage chip 流水线实时重排（必经 Stage 绿虚线框）+ 等价命令行回显。教学点: 「全量与裁剪是同一条管道」。
- **视觉**: 蓝 chip + 灰箭头 + 等宽字体命令行，干净但静态。

### 差距

| 维度 | 现状 | 缺口 |
|---|---|---|
| 动效 | 被裁 chip **直接消失**——「裁掉」是状态切换不是事件 | 裁剪应可见地「发生」 |
| 状态反馈 | 勾选有 checkbox 态，管道响应无强调 | 刚消失的是哪个 chip 无提示 |
| 进度感 | 无「管道变短」的度量 | 裁掉几关/剩几关 |
| 叙事性 | 管道静止，「流水线」隐喻无流量感 | — |

### 升级选项

**A. 裁剪动效 + 统计行（轻升级，推荐）**
- 方案: 被裁 chip 先变红划掉（strikethrough + 灰降）再收起（opacity + max-width transition），让「裁掉」是一个 600ms 的事件；管道下方加统计行「裁掉 4 关，剩 8 关——Stage 0/0.5/5 必经不可裁」。
- 技术: 纯 CSS transition + JS 维护 chip 的 exiting class；统计行是 render() 末尾一行 textContent。
- 工时: 1.5h，约 +35 行。
- 分级理由: 直接强化本章教学点（参数=物理裁剪），成本最低。
- 页面长什么样: 勾上 `--no-plan` 的瞬间，「Stage 3 规划+确认」到「Stage 3.7 代码级细化」四个蓝 chip 依次闪红、中间划一道删除线、然后像被剪断的绳结一样逐个收起消失，剩余 chip 靠拢，下方命令行同步长出参数，统计行数字翻动。

**B. 管道流光 + Stage tooltip（轻升级，可选）**
- 方案: 剩余 chip 间箭头改为流动虚线动画（background-position 循环），表达流水线运转；hover chip 弹一句话说明（该 Stage 干什么）。
- 工时: 1h，约 +30 行。分级理由: 氛围强但对「参数裁剪」理解帮助间接，优先级低于 A。
- 红线: 流光动画必须进 prefers-reduced-motion 降级集。

**C. 预设场景按钮（重升级，不推荐现在做）**
- 方案: 「全量 / 快速通道 / 只执行不评审」一键组合按钮。
- 分级理由（为何重且不推荐）: 预设组合的语义必须与 `skills/flow-deep/SKILL.md` 参数速查逐一对真——**内容漂移面新增**（skill 参数一变预设就得跟改），而组件头注释明言当前映射已是「教学简化」。收益依赖内容准确性，维护联动成本高。若做，需在 lint_flowkit.py 加预设-参数一致性断言。

### 红线自查（A 方案）
- API 不动；chip 容器已 flex-wrap；transition 对触屏无依赖；零依赖。统计行数字注意与「必经不可裁」的现有 fs-chip-must 判定逻辑同源（同一正则），避免两处规则漂移。

## 4. budget429.js（72 行）

### 现状

- **交互形态**: 三个步进器（主会话锁定 1 / subagent 0-6 / 其他会话 0-4）→ 大数字总数 + 等式 + 三色文字判定（≤3 安全 / =4 临界 / ≥5 越界）。
- **视觉**: 纯数字计算器，无图形。五组件中**可视化程度最低**（概念却最适合可视化）。

### 差距

| 维度 | 现状 | 缺口 |
|---|---|---|
| 动效 | 数字瞬变、按钮无反馈 | — |
| 状态反馈 | 三色只有文字变色 | **429 是全站最具戏剧性的事件（警报），页面上却没有事件感** |
| 进度感 | 无预算的视觉度量 | intro 自己说「拖动数字感受预算怎么被吃掉」——但页面没有「被吃掉」的图 |
| 叙事性 | 「实测 4 并发即触发」是断言 | 不演示 |

### 升级选项

**A. 预算槽 + 加号即试射（轻升级，推荐——本线视觉收益最大单点）**
- 方案: 步进器旁加一根垂直预算槽（刻度 0-7，顶部红线上标「3 = 安全上限」）。三路并发是三条彩色流从下往上堆叠填格: 主会话蓝恒占 1 格、subagent 绿 N 格、其他会话橙 M 格，各色段有自己的边界标签。点 `+` 的瞬间一个请求小球飞入槽中、对应格子亮起（把步进器变成「派请求」的叙事）；总数 =4 时槽顶触红线格闪黄 + 弹「429 临界」标签；≥5 时整槽红框脉冲 + 顶部横幅「429 Too Many Requests」闪烁两拍。`−` 号则格子熄灭消退。
- 技术: 格子为 div 堆叠 + CSS transition 亮灭；小球飞行用 CSS transform + transition（从按钮到目标格的连线动画）；警报用 @keyframes 脉冲。无需 SVG。
- 工时: 2-3h，约 +70 行（含 CSS）。
- 分级理由: 交互协议完全不变（还是三个步进器），只是加一面「可视化镜子」;72 → ~150 行仍在单文件舒适区；红黄绿三态与现有判定逻辑同源复用。
- 页面长什么样: 页面左侧还是熟悉的三个步进器，右侧立着一根像温度计的预算槽——蓝段永远占着底格（主会话，恒 1 路），连续点 subagent 的 `+`，绿色小球一颗颗飞进槽里摞高；摞到第 4 格时顶上的红色警戒线开始闪黄，标注「429 临界——实测触发点」；再点一下，整根槽红框脉冲，横幅打出「429 Too Many Requests」，判定文字同步变红: 超预算的后果不再是一句描述，是刚发生在你手里的事。

**B. 完整请求-限流-退避实验（重升级，不推荐）**
- 方案: 独立「派一个任务试试」按钮 + 限流后自动退避演示（停发新 agent、主会话接管、retry-after 计时）——把 ch7 恢复协议演成完整闭环。
- 分级理由（为何不推荐）: 交互面与测试面翻倍（~100 行新增）；步进器已承担用户操作角色，独立试射按钮与之语义重叠（先加 subagent 再试射 = 两步做一件事）；退避演示需要虚构时间线，有「编造机制细节」风险。A 方案的「加号即试射」已拿到 90% 戏剧性。

**C. 保留现状**
- 理由: 若追求最小改动，三色文字判定已传达结论。但本组件是「概念最适合图形化 vs 实现最不图形化」落差最大者，保留现状的机会成本也最大——**不推荐**。

### 红线自查（A 方案）
- API: `.fs-budget` 协议、步进器结构、judge() 三态阈值（≤3/=4/≥5）不动，预算槽是 judge() 的第二渲染出口——两处必须同一函数驱动，防判定漂移。
- 移动端: 窄屏时预算槽从右侧改到底部横条（媒体查询，槽旋转 90° 或改横向格条）；小球的 transform 动画用百分比定位避免像素硬编码。
- 零依赖: div + CSS，无 SVG 依赖（SVG 也不违反零依赖，但此处不必）。
- 动画纪律: 脉冲/闪烁进 prefers-reduced-motion 降级集（降级为静态红框）。

## 5. johari.js（71 行）

### 现状

- **交互形态**: 4 题四选（象限按钮带 title 提示）、即时对错 + why、尾部简化声明。无计分、无进度，四卡平铺。
- **视觉**: 与 autodecide 同构的问答卡。

### 差距

| 维度 | 现状 | 缺口 |
|---|---|---|
| 动效 | 反馈瞬现 | 次要 |
| 状态反馈 | 对错色有 | 次要 |
| 进度感 | 无已答计数，答没答完靠滚动目测 | 次要 |
| 叙事性 | **乔哈里视窗的本命图形是 2x2 四象限网格，页面上没有网格**——四个象限只是一排按钮 | **概念图形缺失，五组件中最重**。读者答完题可能仍不知道「视窗」长什么样 |

### 升级选项

**A. 象限网格化（轻升级，推荐）**
- 方案: 每题选项从一排按钮改为一个 2x2 网格（列标「用户知道/用户不知道」，行标「AI 知道/AI 不知道」——轴标签常驻第一题，后续题复用网格但轴标签淡化为图例）。格内放象限名 + 该题情境化短提示；点选整格。答对时格子绿色填充 + 轴标签高亮（把「为什么是这一格」用坐标系 itself 讲一遍）；答错时正确格闪绿边示意。头部加已答计数 `3/4`。
- 技术: CSS grid 四格 + 轴标签绝对定位或 grid 外框；点击/填充纯 class 切换 + transition。
- 工时: 2-3h，约 +60 行。
- 分级理由: 补的是**概念本命图形**而非装饰——乔哈里视窗在 prompt 技能文档里就是以四象限定义的，页面上补齐这个图形是叙事完整性问题。DOM 结构小改，协议不动。
- 页面长什么样: 原来一排四个小按钮的位置，现在是一张 2x2 田字格——顶上横轴「用户知道 | 用户不知道」，左侧竖轴「AI 知道 / AI 不知道」；读到「XYZ/YYY 是内部概念」那题，点了左下「独有知识」格，整格泛起绿色，两根轴标签同时亮起，反馈条解释「用户知道、AI 不知道——这就是第四象限」: 答题的同时，视窗的坐标系被焊进记忆。

**B. 保留现状 + 最小补丁**
- 方案: 只加已答计数 + 反馈展开动画（~15 行）。
- 分级理由: 教学闭环（判定-反馈-why）已成立; 排期紧时的止损选项。

**C. 拖拽归位（重做，不推荐）**
- 方案: 题卡拖进四象限判定。
- 分级理由（为何不推荐）: HTML5 DnD 移动端表现差，Pointer Events 手写拖拽约 +150 行且触屏体验难保证——**直接顶撞移动端红线**；点选已足够表达判定，交互形态升级不带来新认知收益。重做需强理由，此处没有。

### 红线自查（A 方案）
- API: `.fs-johari` 协议不动；QUADS/CASES 数据结构不动（网格只是 OPTS 渲染层变体）。
- 移动端: 2x2 网格在窄屏天然可用（每格文字短，象限名 + 6-8 字提示）; 轴标签在 <420px 时可简化为格内前缀色块。
- 零依赖: CSS grid + class 切换，无依赖。

## 6. 分级结论一览

| 组件 | 推荐分级 | 推荐方案 | 核心理由 | 工时 |
|---|---|---|---|---|
| replay.js | **轻升级** | A 播放器成熟化 | 补打字机/进度条/先发生后解读; 两处复用杠杆最大 | 2-3h |
| budget429.js | **轻升级** | A 预算槽 + 加号即试射 | 可视化落差最大、概念最适合图形化; 协议零改动 | 2-3h |
| johari.js | **轻升级** | A 象限网格化 | 补概念本命图形（2x2 视窗），叙事完整性问题 | 2-3h |
| switch-panel.js | **轻升级**（优先级最低） | A 裁剪动效 + 统计行 | 强化「参数=物理裁剪」教学点 | 1.5h |
| autodecide.js | **保留现状**（或顺手做 A） | 判定链揭示动画是唯一值得做的增量 | 功能完成度五者最高; 排期紧则不动 | 0-2h |

**总判断**: 五组件无一需要重做/重升级——replay 的 Stage 侧栏（C）和 budget 的退避实验（B）两个重方案均建议缓行或不做，理由分别为协议扩展维护成本与交互面翻倍。全线的正确姿势是**四个定向轻升级**（replay → budget → johari → switch，合计 8-10h），autodecide 视排期取舍。统一纪律: 所有动画进 `prefers-reduced-motion` 降级集; budget 双出口渲染必须同函数驱动; switch 统计与必经判定同源。
