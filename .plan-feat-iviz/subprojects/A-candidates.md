## 0. 评分口径（统一定义）

**核心判据——aha 时刻**: 一个原理值得交互，当且仅当它有一个「看完动画秒懂、纯文字难讲清」的认知增量。每条候选必须能回答「不用动画会损失什么」；答不出的（纯列表型、纯定义型、纯结构型机制）一律不入选。

**价值分（1-5，0.5 粒度）= aha 强度 × 受众面**:

| 分 | 定义 |
|---|---|
| 5 | 机制是 flowkit 核心卖点，且认知增量本质上是**时序/动态/量变**的（临界感、渐进恶化、吞噬率），文字只能给结论 |
| 4 | aha 明确且服务 P1+P2 双受众，或机制代表性强（缺了它教程站明显缺一块） |
| 3.5 | aha 真实但单点较薄，或受众偏窄（P2 工程原理学习者为主） |
| ≤3 | 有微弱动态感但静态图可承载大半（本清单不收，见否决区） |

**难度分（1-5，0.5 粒度）= 原生 JS+SVG+CSS 无框架实现工作量**:

| 分 | 定义 |
|---|---|
| 1-1.5 | 纯 CSS 切换/hover/微动效，<150 行 |
| 2-2.5 | 单组件 + 少量状态，200-400 行；或**复用既有 replay JSON 剧本管线只写数据** |
| 3-3.5 | 需状态机 + SVG 动画/曲线绘制，400-700 行 |
| 4-5 | 需模拟引擎、多实体编排、大量剧本数据，>800 行 |

**既有组件事实底账**（影响升级类候选的难度分）:
- `replay.js` 是**通用回放器**（JSON 剧本驱动，`data-script` 挂载），已跑 ch4-pipeline / ch8-autohandoff 两个剧本——「情景回放」管线现成，新增情景 ≈ 只写 JSON
- `autodecide.js`（ch6·P1-P6 单条判定链）/ `budget429.js`（ch7·静态快照计算器）/ `johari.js`（ch5·象限判定）/ `switch-panel.js`（ch1·参数开关）

**落位对照**（site 现有 11 章）: 原理篇 ch1 Agent Loop / ch2 长时程三板斧 / ch3 记忆闭环; 机制篇 ch4 管道全景 / ch5 输入质量 / ch6 评审决策 / ch7 并发执行 / ch8 上下文工程 / ch9 验证迭代 / ch10 跨会话记忆 / ch11 编排治理。

## 2. 逐条详述

### C1 · Auto-Decide 批量吞噬漏斗（升级）

- **机制**: D2 Auto-Decide Layer——6 原则 P1-P6 逐一判定命中即停，自动处理约 80% 常规发现，用户只看 <5 条 Taste Decision
- **R3 域**: D（评审与决策）
- **已有一期**: ch6 `autodecide.js` 走**单条**发现的判定链
- **aha 时刻**: 20 条评审发现流入漏斗，绝大多数被 P1-P6 逐条「吞掉」，只有零星几条穿出落在用户面前——「决策疲劳治理」从数字变成体感
- **不用动画的损失**: 「80% 自动处理、20+ 条变 <5 条」只是 README 里的两个数字; 漏斗的吞吐过程、每条被哪条原则命中即停的**分拣感**，文字给不出
- **候选动效形态**: ① 漏斗流: 发现卡片逐条滚入，命中原则即变色被吞，幸存者落入 Taste Decision 托盘（可点卡片回看它为何幸存）; ② 批量模式挂在现有单条模拟器之上，作为「第二幕」
- **价值 5 / 难度 2.5**（复用 autodecide 的判定数据结构，加批量编排层）
- **落位**: ch6 现有组件扩展

### C2 · Context Rot 三策略对比曲线

- **机制**: F4/F5 Context Guard 真值检测 + Auto Handoff 75% 接力——context rot: 上下文越满质量越差，直到 auto-compact 粗暴压缩
- **R3 域**: F（上下文工程）
- **已有一期**: ch8 `replay.js` 跑 ch8-autohandoff 剧本（单策略接力情景）; 曲线对比是新形态
- **aha 时刻**: 同一个长任务三条曲线并跑——「不管」线渐进恶化后断崖; 「只靠 auto-compact」线压缩瞬间丢细节台阶式劣化; 「Auto Handoff」线 75% 处主动断开、新会话接力后回到高位——三条线分岔的瞬间就是 flowkit 存在理由的瞬间
- **不用动画的损失**: 「越满越差」的**渐进性**与 75% 临界点的**时机感**是纯时序认知，文字只能给「context rot 有多可怕」的结论; 三策略对比表给不出分岔画面
- **候选动效形态**: ① 三线赛跑图（SVG path 动画，横轴任务进度、纵轴输出质量，75% 竖线 + 交接旗）; ② 时间轴可拖动回放每时刻的上下文占用条（与三条曲线联动）
- **价值 5 / 难度 3.5**（SVG 曲线动画 + 简单质量模拟函数，数据可预生成）
- **落位**: ch8 主视觉（现有 replay 情景可保留为伴生）

### C3 · keep/revert 轨道 + 渐进 Guard

- **机制**: G9 auto-iterate——每次一个聚焦变更→机械验证→通过 keep 失败 revert; G10 渐进式 Guard（前 1/3 仅 verify / 中 1/3 轻量 / 后 1/3 全量）
- **R3 域**: G（验证与迭代）
- **aha 时刻**: metric 曲线向 target 爬升，每次迭代是一枚有界赌注——失败的竖线**弹回**上一个 keep 点不留痕，绿色区间只进不退; 「安全网」在失败弹回的一瞬间被看见
- **不用动画的损失**: revert 的「失败不留痕」与 keep 区间「只进不退」是状态机语义，文字描述读者要自己在脑内模拟; 三段 Guard 的松紧变化也需要时间轴才有「探索期宽容、精调期严格」的体感
- **候选动效形态**: ① 轨道赌注图: baseline→target 区间，逐次迭代动画（可单步可自动播放），失败弹回 + guard 强度用背景色三段渐变; ② 用户手动点「再试一轮」驱动，参数从 Stage 5 失败项自动构造的过程可作开场幕
- **价值 5 / 难度 3**（单实体状态机 + SVG 曲线，剧本数据 10-15 轮迭代预生成）
- **落位**: ch9（该章现无交互组件，是最大空档）

### C4 · 并发预算生命周期模拟（升级）

- **机制**: E7 规模档位与并发硬约束——有效并发 = 主会话(恒1) + 运行中 subagent + 其他活跃会话; 429/1302 后暂停分发 + 主 Agent 接管 + 退避恢复; 2026-09-11 上限 2→3 的演化线
- **R3 域**: E（执行与并发）
- **已有一期**: ch7 `budget429.js` 静态快照计算器（拖数字看当前有效并发变红）
- **aha 时刻**: 预算不是快照是**流水**——agent 占着名额直到完成，分批派发要在「名额释放」的节奏上踩点; 429 触发瞬间全场降速、退避后恢复的呼吸感
- **不用动画的损失**: 现有计算器给「当前是否超」的静态答案，给不出「预算被长任务持续占用」的时间维度与 429 后的处置时序（暂停→接管→恢复三步）
- **候选动效形态**: ① 时间轴泳道: 3+1 个名额槽，agent 条按时长占用/释放，用户点「再派一个」体验撞线与退避; ② 保留现有计算器作「第一幕（静态）」，时间轴作「第二幕（动态）」
- **价值 4.5 / 难度 3**（泳道甘特式 SVG + 占用/释放状态机）
- **落位**: ch7 现有组件扩展

### C5 · 红旗话术流中拦截

- **机制**: G2 Rationalization Table——每条铁律配红旗话术表（「太简单不需要测试」「应该能工作」「just this once」），内部推理出现即停; G3 Delete-Means-Delete 作其中一幕
- **R3 域**: G（验证与迭代）
- **aha 时刻**: Agent 推理文本逐字流出，红旗话术混在正常推理里——亮起并被铁律拦截的一瞬，读者发现「我自己刚才也没认出来」
- **不用动画的损失**: 红旗话术的**伪装性**——表格里列出来人人会背，但在推理流里与合理叙述混在一起时极难分辨; 「出现即停」的拦截时机感也只有打字机流能给
- **候选动效形态**: ① 打字机推理流 + 红旗高亮冻结 + 弹出「为什么是绕过/正确做法」对照卡; ② 小测模式: 三段推理让用户先猜哪段有红旗，再放动画揭晓（R3 备选「翻牌配对」的进化版）
- **价值 4.5 / 难度 2.5**（文本流 + 高亮状态，剧本即 Rationalization Table 原文，SC5 同源最容易）
- **落位**: ch9（与 C3 同章成对: C3 讲循环、C5 讲纪律）

### C6 · STATE.md 断点恢复情景剧

- **机制**: F1/F3 活记忆 + 恢复协议——/clear 或溢出重置后「读取一次即知当前位置」; 按 Stage 分路径恢复（0-2 重做 / 3 重新规划 / 4 从 Phase Progress 继续 / 5 重新验证）; C5 五件套「对话是易失内存、文件是持久磁盘」
- **R3 域**: F（上下文工程）+ C（思考与规划）
- **已有一期**: 部分——ch8 replay 讲了 75% **主动**接力（Auto Handoff）; 本条讲**被动**断（/clear 轰炸）后怎么救，互补不重复
- **aha 时刻**: 左侧会话窗口被 /clear 整个炸空白，右侧 STATE.md 文件纹丝不动——新会话读一行、进度条直接跳回中断位置的「断点续传」瞬间
- **不用动画的损失**: 「无损恢复」的**无损感**来自炸毁与幸存的并置对比，静态图给不出「先失去再找回」的情绪节奏; 按 Stage 分路径的存在感（同一动作五种恢复深度）也需要分支可视
- **候选动效形态**: ① 复用 replay.js 管线写第三个剧本（双窗对照 + 五路恢复分支选择）; ② 加一个交互开关: 用户选择「中断发生在 Stage 几」→ 看对应恢复路径
- **价值 4.5 / 难度 2.5**（replay 管线现成，主要是剧本 JSON + 少量双窗视觉）
- **落位**: ch8（检测层之后、handoff 之前插「最坏情况」节）

### C7 · nothing missed 分片勾销

- **机制**: E5 分片覆盖验收——任务分解为互斥且完备分片显式列清单，每个 agent 返回后逐项勾销，未覆盖 SendMessage 补查
- **R3 域**: E（执行与并发）
- **aha 时刻**: 验收清单逐项打勾，最后**总有一片没人认领**变红——「分片有遗漏、汇总必有遗漏」从口号变成用户亲手造成的失败
- **不用动画的损失**: 勾销过程和「漏一片全盘皆输」的完备性检查体感; 尤其互动版（用户自己拖任务进分片框）能让「互斥且完备」从抽象约束变成手感
- **候选动效形态**: ① 自动演示: agent 返回→对应分片卡打勾，孤儿分片闪烁补查; ② 互动版: 用户把 8 个子任务拖进 3 个分片，故意留漏洞看汇总缺口（两种难度递进）
- **价值 4.5 / 难度 2.5**（卡片 + 勾销状态 + 简单拖拽）
- **落位**: ch7 分片节

### C8 · 沉没成本 vs 独立审查

- **机制**: C8 Plan Review（Stage 3.5）——全新上下文的 Staff Engineer Agent 审查，消除「第一个 Claude 花时间想方案不愿推翻」的沉没成本偏差
- **R3 域**: C（思考与规划）
- **aha 时刻**: 双 Agent 并排: 作者 Agent 随投入时长增加「护短度」上升（NEEDS_REVISION 越来越说不出口），审查 Agent 无包袱直接亮红——两条心理曲线反向拉开
- **不用动画的损失**: 沉没成本是**随投入增长的动态心理量**，表格说「审查 Agent 没有这包袱」只是断言; 曲线反向拉开的瞬间才让人懂为什么必须是「全新上下文」
- **候选动效形态**: ① 双 Agent 对照卡 + 投入-开放度反向曲线; ② 剧场版: 同一份 plan 在两个上下文里被评审，弹幕式内心独白对比
- **价值 4 / 难度 3**（双实体 + 简单曲线; 剧场版可复用 replay 管线降难度）
- **落位**: ch6「两个 Claude」节（现章节已有该叙事，缺交互锚点）

### C9 · Fast/Full 风险路由分流

- **机制**: E3 风险路由——按任务性质（只读 vs 写入）分流: 只读走 Fast Path（轻量上下文→分片→一行预告→直接分发→勾销）; 写入走 Step 0-5 完整方案确认
- **R3 域**: E（执行与并发）
- **aha 时刻**: 同样一句「fan out subagents」落下，路由器识别只读/写入的瞬间把流量劈成两半——一条管道轻快直通，一条关卡重重，**风险决定流程重量**
- **不用动画的损失**: 分流的**瞬间判断感**与两条管道的重量对比（Fast 一闪而过 vs Full 步步确认），mermaid 双图并排也给了对比但给不出「同一句话被劈开」的因果瞬间
- **候选动效形态**: ① 路由器分流动画: 输入一句话（或选预设任务卡）→ 特性检测高亮「只读/写入」→ 双管道动画展开竞走对比; ② 与 ch7 首节 ASCII 全景图同构，动画版落位即替换感强
- **价值 4 / 难度 2.5**（分流状态机 + 两列步进动画）
- **落位**: ch7 首节（「先路由」）

### C10 · pane 生命周期治理（泄漏累积）

- **机制**: E12 完成即总结即收（总结→TaskStop→list-panes 验证）; E17 三层清理; E13 续接裁决门（续派复用 vs 立即收）——mailbox 型 agent 完成后进程常驻不退出，不收则 pane 泄漏（实测挂 7 分钟）
- **R3 域**: E（执行与并发）
- **aha 时刻**: tmux pane 网格里，完成的 agent 变 idle 灰色但**不消失**——不开「即收」开关，灰色 pane 一个个堆积挤占屏幕; 开关打开，完成→总结→回收一气呵成，网格始终干净
- **不用动画的损失**: 「完成≠退出」的反直觉（多数人默认任务完进程就退）与泄漏的**累积感**——静态截图只能展示「挂了很多 pane」的结果，给不出堆积过程的时间压迫
- **候选动效形态**: ① tmux 网格模拟: 多 agent 完成/idle/泄漏三态，用户控制「即收协议」开关对比两种时间线; ② 裁决门小节: 完成通知到达时弹出「还有下阶段?」二选一（续接复用 / 立即收）
- **价值 4 / 难度 3**（网格布局 + 三态生命周期状态机）
- **落位**: ch7 tmux/分发节

### C11 · 喂模式前后回答质量对比（升级）

- **机制**: B2 乔哈里视窗第四象限——人知 AI 不知的独有知识不喂（举例/定义字典/RAG）则评分 ≤2 封顶，AI 只能瞎猜
- **R3 域**: B（目标与输入质量）
- **已有一期**: ch5 `johari.js` 象限判定
- **aha 时刻**: 同一段需求，不喂时 AI 给出**貌似合理实则错误**的答案（自信地错），喂模式后同一个问题答得精准——「瞎猜长什么样」第一次被看见
- **不用动画的损失**: 错误答案的「貌似合理性」——不展示具体的错，读者以为「AI 猜个大概也还行」; 前后对照的翻转感是说服力核心，文字描述两个版本无冲击
- **候选动效形态**: ① 双栏翻转卡: 左「不喂」栏流式打出自信的错误方案，右「喂模式」栏打出精准版，中缝是喂入的第四象限知识块动画; ② 预设 2-3 个案例（领域术语/私有格式/团队惯例）
- **价值 4 / 难度 2.5**（复用 johari 的案例数据结构 + 打字机双栏）
- **落位**: ch5 第四象限节

### C12 · 记忆复利闭环

- **机制**: H5 Stage -1 强制召回（命中条目全文加载）+ H6 Stage 5.8 验证后沉淀（DONE 才写回）+ H8 交叉授粉——读写双端构成跨任务复利
- **R3 域**: H（跨会话记忆）
- **aha 时刻**: 时间轴上任务 1、2、3…依次跑过，双库节点每次召回命中的连线越来越密——**闭环跑起来的资产增值**，单看任何一环都看不到
- **不用动画的损失**: 「复利」本质是跨任务的**网络生长过程**，静态闭环图（R3 缺口清单里待做的那张）只能给环结构，给不出「越用越准」的时间维度; 「DONE 才沉淀」的闸门（失败方案不进库）也需在动画里被触发一次才可感
- **候选动效形态**: ① 任务时间轴 + 双库网图生长: 每任务召回画连线、沉淀长新节点，故意安排一次 PARTIAL 不写回; ② 交叉授粉彩蛋: 命中条目时同族条目淡淡亮起
- **价值 4 / 难度 3.5**（时间轴 + 网图布局动画，实体多）
- **落位**: ch10 收尾（或 ch3 概念篇的机制落地预告）

### C13 · Fallback 决策树闯关

- **机制**: G8 Fallback 退回 Plan 协议——异常二分: 执行偏差→直接修继续; Plan 假设有误→六步（暂停→记录→分析→更新 Plan→用户确认→继续）; 同一 Phase 2 次 Fallback→退回 Stage 2; 含 G4 三次假设规则与「卡住=缺能力」视角
- **R3 域**: G（验证与迭代）
- **aha 时刻**: 同样「测试挂了」的红色警报，二选一分岔——选「就地硬修」看错误连锁蔓延，选「退回 Plan」看六步走完后干净恢复; 选错路线的**代价对比**是判断力的训练场
- **不用动画的损失**: 二分判断的分岔感与选错的连锁后果（文字描述「会导致连锁错误」是断言，动画让用户亲手选错一次）; 2 次 Fallback 升级退回的计数机制
- **候选动效形态**: ① 二选一闯关: 3 幕情景（各含一次红色警报），用户选路线看后果分支; ② 顶部挂 Fallback 计数器，满 2 次强制退回 Stage 2 的大回退动画
- **价值 3.5 / 难度 3**（分支剧本 + 后果状态动画）
- **落位**: ch9 回退节

### C14 · pretrust 弹窗卡 pane

- **机制**: E11 预信任 cwd——named agent pane 是独立 claude 进程，未信任路径弹 trust 弹窗且后台无面板提示，卡 N 个 pane（2026-09-01 实测）
- **R3 域**: E（执行与并发）
- **aha 时刻**: 分发瞬间 N 个 pane 同时弹出 trust 对话框**集体卡死**——而主会话这边毫无提示，用户不知道为什么任务静默停滞; pretrust 后同样的分发顺畅跑起
- **不用动画的损失**: 「后台的授权等待没有面板提示」的**静默卡死感**——截图只能展示弹窗本身，给不出「主会话无感 + 后台全卡」的不对称信息结构
- **候选动效形态**: ① 双区对照: 上主会话（安静）/ 下 pane 网格（集体弹窗卡住），跑 pretrust 脚本后重放对比; ② 可与 C10 共用 pane 网格底座（同一组件两剧本）
- **价值 3.5 / 难度 2.5**（若与 C10 共底座再降）
- **落位**: ch7 tmux 节（C10 姊妹篇）

### C15 · 复杂度闸门拦截

- **机制**: A5 复杂度闸门——flow-deep 入口执行级确认: 单文件/低风险任务提示降级 /flow，用户坚持则只保留 Goal Contract+Minimal Plan+Verification
- **R3 域**: A（编排与治理）
- **已有一期**: ch1 `switch-panel.js` 参数开关面板（讲双引擎选择），闸门拦截是其下游伴生
- **aha 时刻**: 一个明显简单的任务误入 flow-deep 十二关管道，闸门横杆落下把它**弹回** /flow 三关轻管道——「防杀鸡用牛刀」的拦截瞬间
- **不用动画的损失**: 闸门作为「引擎的最后一道防误用」与选型指南（用户决策）的分工——静态对比表也能讲，动画增量在拦截的动作感与「用户坚持」后的降级保留集演示，增量中等偏薄
- **候选动效形态**: ① 任务卡滑入→闸门评估（体积/风险检测高亮）→分流: 弹回 /flow 或放行（坚持时高亮仅剩的三关）; ② 小体量件，可作 ch1 switch 面板的收尾彩蛋
- **价值 3.5 / 难度 1.5**（单一状态机 + CSS 过渡）
- **落位**: ch1（或 ch4 入口节）

### C16 · 压缩矩阵与不可压缩块

- **机制**: F7 压缩矩阵（Stage 2 压缩 70% / 3.7 压 90% / 中间结果 85%）+ F8 不可压缩清单（Phase 定义/agent_hint files-test-depends/当前 prompt/Stage 5 清单四类必须完整）
- **R3 域**: F（上下文工程）
- **aha 时刻**: 上下文条被压缩变短的一瞬，四类不可压缩块**保持原色不缩**——相对占比反而膨胀，「保命四类」的底线在挤压中显形
- **不用动画的损失**: 压缩比例的**体感**（70%/90% 差多远）与「压缩中什么幸存」的选择性——数字表格给不出挤压过程的视觉权重转移
- **候选动效形态**: ① 上下文条分段动画: 各 Stage 触发压缩时普通块收缩、四类保命块保持，条上方百分比实时跳; ② 可选滑块让用户手动选压缩率看会吞掉什么
- **价值 3.5 / 难度 2**（分段条 + CSS transform）
- **落位**: ch8 压缩节

### C17 · Ralph 封印环（两层循环嵌套）

- **机制**: G13 Ralph Loop——Stop Hook 拦截退出注入一次性固定 prompt，每轮先读 STATE.md 取最新态，Completion Promise 达标输出 `<promise>` 才放行; G16 二分: auto-iterate 是应用逻辑层（怎么迭代），Ralph 是会话控制层（不让停）
- **R3 域**: G（验证与迭代）
- **aha 时刻**: 会话想退出、光标已到出口，被 Stop Hook 封印弹回环内注入下一轮——「不达目的不罢休」的物理感; 与 C3 的 keep/revert 轨道嵌套成**两层循环**全景
- **不用动画的损失**: 「两层不混淆」的嵌套结构（外层封印/内层纪律）静态图可画，但「想退被弹回」的循环强制力与 `<promise>` 达标才开门的解锁瞬间是时序体验
- **候选动效形态**: ① 循环圆环: 出口处 hook 封印图标，每轮注入 prompt 碎片飞入、STATE.md 读取闪一下; ② 与 C3 同屏嵌套（外环 Ralph / 内轨 keep-revert），共享一个案例数据
- **价值 3.5 / 难度 2.5**（单环动画 + 事件序列; 嵌套版与 C3 联动开发更省）
- **落位**: ch9 Ralph 节

### C18 · 需求探索双路径对话对比

- **机制**: B7 双路径——主干明确→轻量 Grilling 一次一问; 模糊想法（3+ 不确定项）→选项式 3-4 选项含推荐; 误用会问爆用户或落入 choice architecture 陷阱
- **R3 域**: B（目标与输入质量）
- **aha 时刻**: 同一个模糊需求走错路径: 一次一问的 Grilling 把对话拖成十几轮的**问卷轰炸**（用户头像逐渐冒火）; 换选项式三轮收束——对话长度的雪茄形对比
- **不用动画的损失**: 「问爆用户」的疲劳是**轮次累积效应**，规则表说「3+ 不确定项走选项式」是静态判定; 对话气泡逐轮堆积的压迫感与两种路径的轮次差只有并行动画给得出
- **候选动效形态**: ① 双列对话模拟: 左 Grilling 列气泡不断追加（带轮次计数器飙升），右选项式列三张选项卡干脆收束; ② 预设一个「模糊想法」案例驱动双列
- **价值 3.5 / 难度 3**（对话流编排 + 轮次计数）
- **落位**: ch5 需求探索节
